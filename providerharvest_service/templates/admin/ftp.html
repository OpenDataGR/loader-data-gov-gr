HTTP box

This is loader itself -- the web pages, the API and the provider pushes. The figures are read live from the machine, which is shared with other projects, so load, memory and disk are the whole machine's.

{{ box_detail(http_box.name, http_box.rows, http_box.commands, http_box.actions, "/admin/ftp/http-box/actions/", "Read just now.", "Figures are not available here.", "/admin/ftp/http-box/logs", http_box.log_services, http_box.charts, http_box.table) }}

Reload workers is safe at any time: loader's worker processes are replaced one by one and nothing is dropped. Restart the whole service restarts all of loader -- the pages, the API, pushes and the FTP boxes' check-ins are unavailable for about 15 seconds and a harvest in progress is cut -- so it asks first and is refused twice within two minutes.

FTP-push accounts

Providers create their own account by registering a push source with FTP/SFTP (it stays disabled until you approve the source). A provider's own account is managed on its source -- password, rotation, allowed senders -- so it appears here read-only, with a link; only accounts an admin made by hand are changed from this page. Passwords are stored only as a one-way hash, so they can never be shown, not even one the provider chose.

Allowed from: with no address listed an account works from anywhere. Once you list any, it works only from those (IPv4 or IPv6 addresses or ranges, FTP and SFTP alike) -- everyone else is refused even with the right password. The box applies a change within about a minute. Only list addresses you are sure of: a provider on a changing address will be locked out. A provider's own account takes its list from the sender addresses on its push source (shown here, edited there).
